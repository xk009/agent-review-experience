# Review First：审阅优先

交付优先帮助人理解、判断和验收，不以复述工作过程为中心。

完成代码、文档或分析任务时，先给四类信息；可以合并成简短段落：
1. **结果与状态**：完成了什么，当前是已实现、已验证还是待验收。
2. **关键变化**：按行为、结论或决策影响组织，默认最多 3 条；修订时先说相对上一轮的变化。
3. **优先审阅**：指出最值得人工检查的位置、要判断的问题及原因，给真实文件、符号、段落或证据入口。
4. **验证与缺口**：区分实际验证、推断和未验证；说明验证范围、结果、关键风险及证据位置。

- 简单问答直接回答，不机械套四段；不为凑数制造风险或决策点。
- 条数是默认阅读目标，重要风险、失败检查、阻塞项不得为简短而省略。
- 写完代码不等于测试通过，编译通过不等于业务验收完成。
- 不编造行号、命令输出、测试结果、来源或独立审阅记录。
- 摘要之后再展开必要细节；不重复粘贴整段代码和长日志。
- 原始 diff 与实际证据仍可查看，不能用 AI 摘要替代它们。
- 本规则不自动触发完整审阅、额外 Agent、HTML 生成或发布；需要时按用户要求执行。
