# Review Package

用户输入：$ARGUMENTS

先读取本目录的 `templates.md`，按任务选择结构。参数是自然语言需求，不是可直接拼接执行的 shell 指令。

## 0. 边界与成本
- 默认生成轻量 Markdown 交付包，不修改业务代码，不自动提交、推送、安装或合并。
- 小任务只需摘要、真实变化入口与验证缺口，不为了模板增加长报告。
- 独立预审或 HTML 仅在用户要求时执行；认为有价值但未获授权时先给建议。
- 不把本 Skill 视为沙箱：它不设置工具预授权，仍遵守会话权限与组织策略。

## 1. 确定范围
- 明确任务类型：代码 / 文档 / 数据分析，以及验收目标。
- 代码任务：记录仓库、分支、base/head、比较方式、纳入和排除的文件。
- 不能确认基线或任务归属时，列出待确认点；不要默认所有未提交修改都属于本任务。
- 文档任务：记录新旧源文件或版本。数据分析：记录数据来源、时间窗、样本与指标口径。
- 输出写到 `.claude-reports/<唯一任务标识>/`；不覆盖旧报告。先核实忽略规则，未忽略时提示用户，不擅自修改项目配置。

## 2. 保存可核实的变化与版本信息
代码任务按实际范围读取并保存证据，不能只看一次 `git diff`：
- 已提交变化：对确认的 base 与 head 比较；若采用 merge-base，记录解析后的 SHA。
- 暂存变化：`git diff --cached --no-ext-diff --no-textconv`。
- 未暂存变化：`git diff --no-ext-diff --no-textconv`。
- 未跟踪文件：通过 `git ls-files --others --exclude-standard` 列出；只纳入本任务相关且允许读取的文件。
- 先看 `git status --short`；显式标注删除、重命名、二进制、子模块或无法完整读取的内容。
- 差异按需限到已确认路径；不要执行仓库提供的外部 diff、textconv 或不明脚本。

记录 HEAD、比较基线、暂存区相关 blob 标识，以及范围内工作区和新增文件的内容 SHA-256；删除项写明 deleted。不能计算时写“快照不完整”，不得只凭 HEAD 声称证据完整。
记录生成时间。审阅结束再次核对范围内快照；有变化则标为 stale，需要重新收集变化并重新判断受影响验证，不得只更新时间戳。
文档和分析任务也需绑定源文件版本或内容哈希。哈希仅标识已记录输入，不证明环境与依赖完全一致。

## 3. 建立变化 → 判断 → 证据的对应关系
- 按行为或结论组织变化，不按工具调用顺序复述。
- 每个优先审阅点写清“看哪里、判断什么、为什么值得看”。
- 保留原始差异入口；摘要不能代替源文件。
- 已有验证：记录命令或方法、实际结果、时间和对应快照。只记录实际执行过的结果。
- 不为填满报告自动跑昂贵构建、安装依赖或请求外部服务；需要新增验证时遵守用户授权与项目规则。
- 旧日志只能标成历史证据；不能证明当前快照已验证。环境不足就标未验证。

## 4. 可选独立预审
用户要求时，调用已安装的 `review-auditor`，传入需求、验收标准、快照、真实 diff 和证据路径，不以实现者的自评作为主要输入。
此 Agent 无 shell；由主会话先准备 Git 差异。只要求找问题，不授权修复。
若无法启动独立子代理，标明“独立预审未执行”；可以给同会话自查，但不能冒充独立预审。
收到发现后逐项核实，保留“已确认 / 待确认 / 不采纳及理由”，不要隐藏不同意见。没有发现也不表示可以跳过人工验收。

## 5. 生成交付包
先输出 `review.md`；必要时保存经筛选和脱敏的原始证据，不复制无关源码或敏感日志。
使用 `templates.md` 的通用模板及对应任务扩展。内容不存在就说明原因，不制造测试、问题或决策。
若提供上一轮报告，先给新增 / 修改 / 已解决 / 仍待处理，以及哪些验证因改动而过期。
用户要求 HTML 时复用已安装的 `html-report` 或按相同原则生成阅读视图：
- 首屏呈现结论、需要判断的点、风险与缺口；失败和阻塞项不能默认折叠。
- 规则、方案和细节按需展开；保留真实证据入口。
- 视图来自同一份 `review.md` 事实，不独立改写结论。
- HTML 默认不引用外部脚本、字体、分析服务；日志与代码需转义后作为文本呈现。

## 6. 最后检查与回复
检查文件入口、版本标识、证据对应关系和公开发布边界。
终端只给结果、最重要的审阅问题、验证缺口、交付包路径。
明确本次做了哪些步骤；未执行的预审、测试或浏览器检查如实列出。
