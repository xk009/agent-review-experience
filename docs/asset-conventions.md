# 产物归档与维护约定

本主题的统一源仓库：`xk009/agent-review-experience`。
本约定管理后续工作，不代表已经替用户启用自动上传或后台同步。

## 归档位置

| 产物 | 位置 | 维护原则 |
| --- | --- | --- |
| 调研、方法、实施说明 | `docs/` | 结论先行，附来源、日期和验证边界 |
| 一次性可复制指令 | `prompts/` | 一条任务一个代码块，与 Rules 避免重复 |
| 常驻行为规则 | `claude/rules/` | 简短、跨任务；不塞完整工作流 |
| 按需流程及其模板 | `claude/skills/<name>/` | `SKILL.md` 为入口，依赖随目录提供 |
| 专项子代理 | `claude/agents/` | 最小工具权限，标明输入与能力边界 |
| 输出风格、主题、Hook | `claude/` 现有对应子目录 | 保留兼容性说明，不无声扩大权限 |
| 终端与 Git 配置 | `terminal/` | 示例与真实已安装配置区分，先预览再合并 |
| 脚本与验证 | `scripts/`、`tests/` | 可复现，不默认改用户全局环境 |
| 后续 App 源码 | `apps/<app-name>/` | 真正开发时再建；写清启动、测试和数据边界 |

不要为了目录齐全创建空 App。优先打通一个真实审阅流程，再决定是否需要独立界面。

## 单一事实源

Markdown/结构化数据作为可维护源；HTML 为需要时生成的阅读视图。
一份结论不要在两份文档里分别手工维护。新增产物更新 README 导航。
通用规范只有一个权威版本，其余文档以链接引用。

## 安装与版本

仓库的 `claude/` 只是源文件，不会因 clone 自动成为全局配置。
新安装和升级均先预览差异；不得直接覆盖用户的 settings、CLAUDE.md、终端设置或权限规则。
写明文档核对、脚本测试与实际客户端端到端测试分别完成了哪些。

## 公开发布边界

仓库用于公开的通用模板、脱敏案例与工具。业务仓库里的源码、原始任务日志、内部链接、账单、令牌和个人数据不自动归档到这里。
业务审阅包先保留在对应业务环境的受控目录；提炼可复用经验后再脱敏入库。
生成 HTML 时注意外部 CDN、字体、遥测和脚本的数据外发风险。
“后续所有产物放这里”不授权自动发布任何敏感内容，也不意味着每次使用 Skill 都自动 commit/push。

## 提交习惯

按一个可审阅的主题提交，写明做了什么、验证了什么、尚未验证什么。
不要覆盖他人的并行改动；发现 HEAD 变化时重新核对。
真实测量前，不宣传具体提效倍数、百分比或成本下降。
